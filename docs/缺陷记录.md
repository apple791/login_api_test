# 教学缺陷记录

下列缺陷均为主动植入的本地教学缺陷。预期来自项目规则，不根据缺陷模式更改断言。

## B01 密码下限比较错误

- 前置：以 lower_bound 模式运行，使用未注册用户名。
- 输入：POST /api/register，username=learner，password=aaaaaa。
- 预期：201，6 位属于合法边界。
- 实际：400，错误拒绝注册。
- 原因：app.py 中缺陷分支将 minimum 从 6 改为 7。
- 修复练习：在副本中移除该错误覆盖或改回 6，仍使用 lower_bound 执行原用例；6 位应成功，5 位仍应拒绝。
- 回归：原失败用例通过后执行全部测试，不仅验证6位。

## B02 密码上限校验遗漏

- 前置：upper_bound 模式，每次使用独立未注册用户名。
- 输入：17 位密码，另用20位密码作为无效等价类复核。
- 预期：400，不能创建账号。
- 实际：201，超长密码被接受。
- 原因：错误分支将 maximum 设置为当前输入长度，失去16位上限。
- 修复练习：保持 maximum=16，原模式下重新执行；16位应成功、17位应拒绝。

## B03 未登录访问被错误放行

- 前置：no_auth 模式。
- 步骤：不带 Authorization 请求 GET /api/me。
- 预期：401。
- 实际：200，返回教学用虚拟 guest。
- 原因：缺失请求头时提前返回成功，绕过认证。
- 修复练习：删除错误放行分支，使其走正常401判断；有效 Token 仍应能够查询本人信息。

## 如何用于面试

明确说明这是带预设缺陷的个人练习。描述依据、输入、预期、实际、定位和回归。不要说成在公司发现了线上问题，也不要把切换 correct 模式描述成自己已经修复代码。
