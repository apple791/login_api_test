# 当前用例组织与数据管理

更新日期：2026-10-18。本文描述当前状态，历史结果见带历史标识的验证文档。

## 结构

账号六个文件39条；账本接口按新增、金额、权限、会话、列表五个文件拆分，共56条；SQL核对独立文件12条。默认test_cases共107条。配置在config.py，共享夹具在根conftest.py；SQL文件局部ledger_account夹具负责获取用户身份，避免重复请求代码。

## SQL核对

成功新增同时核对记录归属、全部字段、整数分金额和数量增加；非法金额核对400、data为空及当前用户数量不变；列表SQL核对全部返回字段与顺序；分类汇总先确认其他用户干扰数据实际入库。原嵌套在另一测试内部的列表SQL函数已移到顶层，修复漏收集，因此106条增至107条。

SQL连接由fixture通过yield提供，finally关闭；DB_PATH为本机正常模式数据库路径，不能仅改远程服务地址却继续查本机库。不得把分类汇总描述为统计接口测试。

## 两套测试

test_cases需要真实HTTP服务，当前107条在独立临时服务与其匹配数据库验证通过；tests自建临时服务或客户端，119条在本阶段此前验证通过。两套覆盖重叠，不合并宣传独立场景数量。

verify_modes.py只运行tests/test_auth.py与tests/test_account.py的81条，检查四种模式的预期失败数。此次文档更新未重跑四种模式。
