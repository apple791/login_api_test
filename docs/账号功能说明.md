# 账号功能说明

## 修改密码

POST /api/change-password，携带 Authorization: Bearer TOKEN，JSON 字段为 old_password 和 new_password。

处理顺序：校验 Token 和会话 → 校验原密码类型及新密码规则 → 比对原密码摘要 → 拒绝相同密码 → 更新密码摘要并删除该账号全部会话 → 返回200。

新密码为6～16位 ASCII 字母或数字，包含端点。缺失、null、类型错误、空格、中文、符号均返回400。原密码错误返回401，密码相同返回400；任何失败都不改变密码或登录状态。

修改成功后必须重新登录。查询个人信息、退出、再次改密都不能继续使用旧 Token。其他账号不受影响。

## 退出登录

POST /api/logout，携带 Authorization: Bearer TOKEN，不需要请求体。

处理顺序：校验 Token 和会话 → 删除当前会话记录 → 返回200。重复退出返回401。不会改变账号密码，也不影响同账号的其他会话。

## 为什么增加 sessions 表

JWT 未到期并不意味着用户仍应保持登录。服务除验证签名和有效期，还要查询会话是否仍存在。

users 保存账号及密码摘要；sessions 保存每次登录的随机 token_id 和 user_id；Token 中的 jti 对应该 token_id。同一秒连续登录也会得到两个不同 Token。退出删一条会话，改密删该用户全部会话。

这次保留简单的 SQLite 结构，不引入 Redis 或刷新令牌。已有数据库启动时自动创建 sessions 表，不删除用户；升级或重启后需重新登录。过期会话的定期清理、并发登录与改密竞争暂未纳入练习。

## 手工练习

1. 注册账号，用相同账号连续登录两次，分别保存 Token A、B。
2. 用 A 退出：A 查询返回401，B 查询仍返回200。
3. 用 B 修改密码：新密码先试5位，再试6位；5位应400且B仍可用，6位应200且B失效。
4. 使用旧密码登录应401，使用新密码登录应200。
5. 使用另一个账号重复步骤，检查账号之间不受影响。

先在 correct 模式练习。教学缺陷模式仍保留原来的三个问题，新功能不额外植入缺陷。
